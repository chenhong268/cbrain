# Health Debt Delta Gate Design

## Problem

CBrain already has `fsck`, `repair-plan`, and `gate:consistency`, but those gates describe the current state. They do not answer the review question after a change:

> Did this issue introduce new hard storage debt compared with the saved baseline?

Raw health totals are noisy because historical debt can be large. The first useful control is not to clear every old issue; it is to prevent new hard debt from entering the system.

## Goal

Add a deterministic delta gate that compares a previous consistency-gate JSON report with the current consistency-gate report.

The gate fails only when hard findings are newly introduced or increased. Existing hard findings with the same or lower counts do not fail this delta gate, because they are historical debt. Warning increases are reported but do not fail the gate.

## Non-goals

- No automatic repair.
- No health system rewrite.
- No fsck probe behavior changes.
- No historical debt cleanup.
- No LLM or MoA.
- No public fixture with private knowledge.

## Design

### Input

The baseline input is a JSON file produced by `bun run gate:consistency` or by `bin/check-consistency-gate.ts`.

The current input is generated by running the same consistency gate logic in-process:

1. load CBrain config;
2. run fsck;
3. build repair plan;
4. evaluate consistency gate.

### Pure Evaluator

Create `src/core/fsck/debt-delta-gate.ts`.

It exposes:

```ts
export interface DebtDeltaGateReport {
  gate: "health-debt-delta";
  version: "1";
  timestamp: string;
  passed: boolean;
  status: "pass" | "warn" | "fail";
  baseline: DebtSummary;
  current: DebtSummary;
  new_hard: DebtDeltaFinding[];
  warning_deltas: DebtDeltaFinding[];
  next_action: string;
}

export function evaluateDebtDeltaGate(
  baseline: ConsistencyLikeReport,
  current: ConsistencyLikeReport,
  timestamp?: string,
): DebtDeltaGateReport
```

The evaluator keys findings by `layer + check`. For each key it compares aggregate `count`.

Rules:

- `new_hard`: current hard count greater than baseline hard count.
- `warning_deltas`: current warning count greater than baseline warning count.
- `status = "fail"` when `new_hard.length > 0`.
- `status = "warn"` when no new hard debt exists but warning deltas exist.
- `status = "pass"` when neither hard nor warning debt increased.
- `passed = status !== "fail"`.

Samples are forwarded only from already-anonymized consistency-gate findings. No raw fsck report is emitted.

### CLI Gate

Create `bin/check-health-debt-gate.ts`.

Usage:

```bash
bun bin/check-health-debt-gate.ts --baseline baseline.json
```

Exit codes:

- `0`: pass or warn.
- `1`: fail due to new hard debt.
- `2`: missing/invalid baseline or missing DB.

Add package script:

```json
"gate:health-debt": "bun bin/check-health-debt-gate.ts"
```

### Privacy

The output must not include:

- local filesystem paths;
- database paths;
- raw slugs from fsck;
- stack traces;
- private content.

Invalid baseline errors use fixed strings and do not echo file paths.

## Tests

### Pure Tests

Create `tests/core/fsck/debt-delta-gate.test.ts`.

Cover:

1. clean baseline/current passes;
2. new hard finding fails;
3. same hard count passes;
4. lower hard count passes;
5. increased warning returns `status="warn"` but `passed=true`;
6. output does not expose raw slug strings if samples are anonymized.

### CLI Tests

Create `tests/cli/health-debt-gate.test.ts`.

Cover:

1. clean DB + clean baseline exits 0;
2. page_without_chunks vs clean baseline exits 1 and lists `sqlite.page_without_chunks`;
3. missing baseline exits 2 with privacy-safe diagnostic;
4. invalid JSON baseline exits 2 with privacy-safe diagnostic.

## Effect Evaluation

For future issues:

1. before work, save baseline:

```bash
bun run gate:consistency > /tmp/cbrain-consistency-baseline.json
```

2. after work, run:

```bash
bun run gate:health-debt -- --baseline /tmp/cbrain-consistency-baseline.json
```

This proves whether the issue introduced new hard storage debt, independent of historical debt volume.
