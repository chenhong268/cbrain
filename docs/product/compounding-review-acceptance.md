# Compounding Review — 复利反馈验收标准

> 验收 #94 的"低频复利反馈"能力定义。防止实现偏离产品契约。
>
> 产品契约：`docs/product/conversation-compounding-contract.md` — Journey 4: Low-Frequency Compounding Review

## 适用范围

CBrain 累积到足够记忆后，在用户**未主动请求**的情况下，主动呈现一条高价值的结构化反馈。核心原则：**沉默比噪音好**。

## 什么是 Compounding Review

一条 Compounding Review 是 CBrain 主动向用户呈现的、基于累积记忆的结构化观察。它**不是**搜索结果、**不是**摘要、**不是**工具输出。它是 CBrain 从用户自己的记忆中发现的新理解。

### 一条 Review 的形态

```
[一句话观察]（≤ 30 字）

依据：
- 证据条目 1（来源标签 + 日期范围）
- 证据条目 2（来源标签 + 日期范围）

[可选] 注意：...
```

**硬限制**：
- 总长度 ≤ 150 字
- 证据条目 ≤ 3 条
- 每条证据 ≤ 40 字
- 一次只呈现 1 条 Review

## 评分维度

一条候选观察必须通过**所有 5 个维度**的阈值才能成为 Review：

| 维度 | 含义 | 最低要求 |
|:-----|:-----|:---------|
| **Evidence** | 是否有多条独立证据支撑 | ≥ 3 条来自不同来源的证据 |
| **Persistence** | 是否跨时间持续出现（非一次性巧合） | 跨越 ≥ 2 个独立时间点 |
| **Novelty** | 用户是否大概率还不知道 | 不应与用户已知的明确结论重复 |
| **Action Value** | 知道后是否可能改变判断或行动 | 能在 1 句话内说明"为什么现在值得关注" |
| **Trust Risk** | 呈现后是否可能误导 | 不得包含 candidate 级内容作为 fact；必须标注信任状态 |

**任一维度不达标 = 不呈现。沉默是正确行为。**

## 何时沉默

以下情况**必须**返回沉默（不生成 Review）：

| 场景 | 原因 |
|:-----|:-----|
| 证据不足（< 3 条独立证据） | Evidence 不达标 |
| 仅单次出现（无持续性） | Persistence 不达标 |
| 结论是用户已知的明确记录 | Novelty 不达标 |
| 呈现后无法说明"为什么现在值得关注" | Action Value 不达标 |
| 信任状态为 candidate 或 rejected | Trust Risk 不达标 |
| 用户已拒绝过相同观察 | Rejection memory 生效 |
| 无符合条件的候选 | 沉默是默认行为 |

## 用户动作

| 动作 | 含义 | 系统行为 |
|:-----|:-----|:---------|
| **accept** | 确认观察有价值 | 记录用户确认该 review candidate 有价值；底层事实/关系/证据的 trust_state 不因 accept 自动升级，除非另走 confirm_evidence 等确认链路 |
| **reject** | 拒绝观察 | 记录拒绝，同源观察不再重复提议 |
| **defer** | 暂不处理 | 沉默保留，不再次主动呈现 |
| **disable** | 关闭 Compounding Review | 停止所有主动反馈直到重新开启 |

## 隐私规则

| 规则 | 说明 |
|:-----|:-----|
| 社交情境内容默认不呈现 | 涉及 user_thought、人物关系时需额外审查 |
| 不主动建议联系某人 | 即使检测到关系变化，也不推荐社交行为 |
| 占位符强制 | 所有 fixture、示例、文档使用 `人物A / 主题B / 事件C / 资料D / 组织E / 地点F` |
| 无真实人名/组织名/地点 | 禁止在任何验收材料中出现可识别信息 |

## 验收场景

### 场景 1：主题收敛（应呈现）

**输入状态**：近 3 个月内，多条记录（≥ 3 条，来自不同时间点和来源）围绕同一未解决主题（如"人物A 在 主题B 上的立场变化"），且该主题在用户的已有知识中未被明确总结。

**预期输出**：一条 Review，说明多条记录收敛于该主题，附证据来源。

**预期字数**：≤ 150 字。

### 场景 2：跨主题关联（应呈现）

**输入状态**：两条此前无关联的主题（如"主题B"和"主题D"），在 ≥ 3 条独立证据中出现共同元素或因果线索。

**预期输出**：一条 Review，说明两条线的关联，附证据来源。

### 场景 3：观点变化（应呈现，但标注为"可能变化"）

**输入状态**：用户在时间点 T1 对 主题B 有明确判断（user_thought），在时间点 T2（≥ T1 + 1 月）有相反或明显不同的判断。仍需 ≥ 3 条独立证据支撑（如 T1 前后各至少 1 条佐证 + 变化点本身）。

**预期输出**：一条 Review，标注为"可能变化"而非定论。不得将 T1 或 T2 的观点陈述为客观事实。

**禁止**：说"你的观点从 X 变成了 Y"——必须说"在 主题B 上，前后记录存在差异"。

### 场景 4：弱巧合（应沉默）

**输入状态**：两个实体在同一篇文章中被提及，但无其他独立证据支撑关联。

**预期输出**：沉默。不生成 Review。

**原因**：Evidence = 1（< 3），Persistence = 1（单次）。

### 场景 5：已拒绝观察（应沉默）

**输入状态**：CBrain 曾提出"主题B 和 主题D 有关联"，用户 reject。后续无新证据。

**预期输出**：沉默。同源观察不重复提议。

### 场景 6：社交情境内容（需隐私审查）

**输入状态**：Review 候选项涉及 user_thought 或人物关系。

**预期输出**：不默认呈现。如呈现，必须标注来源为"你的观点"，且不主动建议联系相关人物。

### 场景 7：无高价值候选（应沉默）

**输入状态**：CBrain 扫描全部候选观察，无一通过所有 5 个评分维度。

**预期输出**：沉默。这是**默认行为**，不是异常。

## 反馈预算

| 类型 | 频率上限 | 说明 |
|:-----|:---------|:-----|
| 即时主动反馈 | 每次回答 ≤ 1 条 | 仅在当前对话上下文中有强相关 Review 时 |
| 周期性 Review | 由系统调度，频率极低 | 无强 Review 时返回沉默 |

## 与现有能力的关系

| 现有工具 | Compounding Review 的区别 |
|:---------|:-------------------------|
| `list_insights` / `read_discoveries` | 系统内部发现列表，用户主动查询；Review 是主动推送 |
| `brain_storm` | 用户请求分析/推理；Review 是无请求时发现 |
| `agentic_research` | 用户请求复杂研究；Review 是单条轻量观察 |
| `reflect` | 维护命令，内部推理；Review 是面向用户的产品体验 |
